# 第七章　总结与展望

## 7.1　工作总结

本文以"基于 etcd 的分布式 Kubernetes 调度器研究与实现"为题，围绕多实例并发调度场景下的一致性保证与大规模性能优化两个核心问题展开研究。以字节跳动开源的 Gödel Scheduler 为基础平台，完成了架构梳理、机制设计与性能优化三方面工作：

（1）分布式调度器架构的系统性梳理。第 3 章明确了 Dispatcher / Scheduler / Binder 三层架构下 Pod 的完整流转过程，特别指出整个分布式调度器不依赖任何自研的分布式协调机制，而是完全基于 Kubernetes 底层 etcd 通过 kube-apiserver 暴露的三种原子性语义（Pod / Node 注解的 `resourceVersion` 乐观并发、Watch 一致性视图、Bind 子资源的原子写入）。这一分析统一了后续章节的论证起点。

（2）基于 etcd 语义的多层一致性容错机制。第 4 章针对分区归属漂移、Bind API 暂态失败、Bind 失败后的 Assumed 状态残留、本地重试耗尽四类典型威胁，设计并实现了包含节点归属前置校验（Layer 0）、同步重试（Layer 1）、异步 Reconciler（Layer 2）、跨 Scheduler 实例回退（Layer 3）的四层容错框架，并给出了核心不变量"任一 Pod 至多绑定到一个节点"的完整证明。

（3）面向大规模场景的 ENO 架构优化。第 5 章提出将原独立部署的 Binder 合并进 Scheduler 进程的架构改造，通过 CacheAdapter 桥接层实现 SchedulerCache 零拷贝共享，消除了跨进程 API 调用与序列化开销，同时保持了第 4 章一致性容错机制的完整性。

第 6 章通过 KWOK 仿真下主对比与扩展两个批次及后续补测（共 144 次留存的基准 run，覆盖 s1~s4 规模、w1~w7 负载与 1/3 实例配置），对 ENO 与四种主流调度器（Gödel、kube-scheduler、Volcano、Koordinator）在有效吞吐、调度延迟、绑定成功率、资源开销等维度进行了系统性对比，验证了本文架构改造的性能优势与一致性保证的可靠性。其中，实例数由 1 增至 3 时 ENO 的 P99 调度延迟下降 99.2%、Pod E2E 延迟下降 97.2%（Gödel 分别为 99.5% 与 97.1%），峰值吞吐提升 61.0%；s4（10000 节点）规模下 ENO 的有效吞吐仍领先 Gödel 5.6%、P99 调度延迟低 33.4%。

## 7.2　主要贡献

本文的两项核心创新与一项辅助产出如下（与摘要及 1.3 节的表述一致）：

- 创新点 1：单 Dispatcher、多独立 Scheduler 的分布式调度架构 ENO（第 5 章）。将 Binder 合并进 Scheduler 进程，通过 CacheAdapter 零拷贝共享消除跨进程开销，同时保持向后兼容与一致性保证；
- 创新点 2：基于 etcd 语义的四层绑定容错机制（第 4 章）。填补了分区调度器场景下节点归属动态漂移的一致性论证空白，给出了核心不变量的完整证明；
- 辅助产出：可复现的多调度器大规模评估平台（第 6 章）。基于公开的 KWOK 仿真平台完成两个批次及后续补测、共 144 次留存的基准 run，覆盖 1000~10000 节点、7 类负载与多实例配置，公开完整的实验方法学与原始数据，为后续研究提供可复现的基线。

## 7.3　局限性

本文工作存在如下局限，坦诚列出：

（1）Gang 场景下 ENO 尾延迟偏高的成因未定量分离。w6（Gang 调度）在负载扩容到 50 000 个 Pod 后补齐了延迟数据，但该场景下 ENO 的单 Pod 尾延迟高于 Gödel，本文的解释是"同组预留等待与后续 Pod 调度决策共用同一进程队列"，尚未通过独立的计时实验把"同组预留等待"与"调度决策 + 绑定耗时"分离开定量验证（见 6.7 节第（2）条）。

（2）生产环境未验证。本文所有实验均在 KWOK 仿真环境下完成，未在真实生产集群中验证。真实节点上的 kubelet 排队、容器启动开销、网络与磁盘 IO 干扰可能对结论产生影响。

（3）ENO 与 Gödel 资源公平性的一维近似。本文的公平对比策略是每 Deployment 的资源规格相同（Scheduler Pod 与 Binder Pod 都是 2 CPU / 4 GB），这一策略在单 Pod 层面保证了公平，但没有系统性量化集群总资源开销层面 ENO 因移除 Binder Deployment 带来的进一步节省。

## 7.4　未来工作

针对上述局限，未来的工作方向包括：

（1）真实生产环境的灰度部署。当前所有实验在 KWOK 仿真环境下完成，未在生产集群验证。未来可考虑与拥有真实生产集群的机构合作，在生产环境中开展灰度部署与观测，检验 ENO 的收益与稳定性。

（2）Binder 内存压力自适应。当前 ENO 的 Binder 与 Scheduler 共享同一进程内存，若集群规模进一步扩大导致 SchedulerCache 显著增长，可能需要在 Scheduler 与 Binder 之间引入更细粒度的内存共享策略（例如按分区分片的 SchedulerCache）。

（3）异地多活 Dispatcher。当前 Dispatcher 采用单实例 Leader Election 模型，对跨地域场景不够友好。可探索多 Dispatcher 分区协同的架构，将节点分区表本身也做分区化管理。

（4）与调度策略研究结合。本文侧重于调度器的架构与一致性，未涉及具体的调度策略（如资源感知、拓扑亲和、拥塞控制等）的创新。ENO 架构为后续在其上叠加具体调度策略研究提供了良好的基础平台。

## 7.5　结束语

分布式 Kubernetes 调度器同时面对一致性保证与大规模性能两个问题。本文以 Gödel Scheduler 为对象，先分析其基于 etcd 原子性语义构建的四层容错机制并给出核心不变量的证明，再提出进程内 Binder 的 ENO 架构改造，并在 KWOK 仿真下的 16 个对比场景中完成实测。工作的边界与未覆盖之处已在 7.3、7.4 两节明确列出。架构分析、代码实现与实验数据均已开源，希望能对后续在这一方向上做工作的人有用。
