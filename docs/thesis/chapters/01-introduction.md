# 第一章　绪论

## 1.1　研究背景与意义

自 2014 年 Google 开源以来，Kubernetes 已发展成为云原生领域的事实标准容器编排平台，被全球范围内的互联网企业、金融机构与科研机构广泛部署。Kubernetes 通过声明式 API 与控制器模式抽象了底层基础设施，使得开发者可以以统一的方式管理计算、存储、网络资源。而在 Kubernetes 的诸多控制器中，调度器（Scheduler）承担着为待运行的 Pod 选择合适 Node 的核心职责，其吞吐量与延迟直接影响整个集群的资源利用率与工作负载响应速度。

Kubernetes 原生调度器（kube-scheduler）采用单实例串行架构，即整个集群中只有一个 kube-scheduler 处于活跃状态处理 Pod 调度请求。这一设计在千节点规模、百级别并发的常规工作负载下运行良好，但在超大规模集群与高并发调度场景中逐渐暴露出瓶颈：

- 吞吐量瓶颈：kube-scheduler 单进程内部通过一个 activeQ 串行处理 Pod，稳态调度吞吐存在明确上限，无法满足在线服务大规模弹性伸缩、批量任务快速启动等场景的调度速度要求；
- 延迟抬升：随集群节点数增长，Filter 与 Score 阶段遍历节点的开销线性上升，P99 调度延迟在 5000 节点规模下明显恶化；
- 单点故障：kube-scheduler 通过 Leader Election 保证单实例活跃，一旦 Leader 崩溃需要等待 Standby 接管，期间集群完全无法调度。

为应对上述挑战，业界与学界陆续提出了多种分布式调度器改造方案，通过将调度职责拆分到多个组件、多个实例并发执行的方式突破单实例架构的性能天花板。然而，分布式改造在带来吞吐提升的同时，也引入了新的关键问题——多实例并发场景下的一致性保证：如何确保任一 Pod 在任意时刻至多被绑定到一个节点、如何处理节点分区归属变更引发的边界情况、如何在 Bind API 暂态失败后正确恢复而不残留脏数据，都需要在系统设计层面给出严谨解答。这些问题的答案高度依赖 Kubernetes 底层存储 etcd 所提供的原子性保证——包括 Watch API 的一致性视图、Pod 资源的乐观并发控制（`resourceVersion` 语义）、以及 Bind 子资源的原子写入语义。

## 1.2　研究目标与主要贡献

针对上述现状，本文围绕大规模分布式 Kubernetes 调度器开展系统性研究，聚焦于大规模性能优化与分布式调度场景下的一致性保证两类核心问题，采用"集中式任务分发 + 分布式调度执行"（即分发-执行解耦）的总体技术路线。研究目标包括：

- 目标一（面向性能优化）：构建单 Dispatcher、多独立 Scheduler 的分发-执行解耦架构，通过节点分区（Sharding）实现多实例无锁并发调度；将 Binder 绑定执行链路合并进 Scheduler 进程，通过 CacheAdapter 共享缓存适配层实现零拷贝状态复用，从根本上消除独立 Binder 引入的跨进程开销与串行化瓶颈；
- 目标二（面向一致性保证）：基于 etcd 的原子性语义，构建覆盖 Bind 前后完整链路的四层结构化容错——节点分区校验、本地重试、异步回收、全局回退，并形式化论证核心不变量"任一 Pod 至多绑定到一个节点"在分区归属动态漂移场景下仍严格成立。

对应上述两个研究目标，本文的主要贡献包括：

创新点 1：单 Dispatcher、多独立 Scheduler 分布式调度架构（ENO）。构建"单 Dispatcher 统一分发 + 多 Scheduler 独立并行执行"的协同模型，使系统整体吞吐能力可随 Scheduler 实例数亚线性扩展（第 6 章 s3/w3 实测：实例数 1→3 时 ENO 有效吞吐 +17.5%、峰值吞吐 +19.2%）。设计并实现了 CacheAdapter 共享缓存适配层，使 Scheduler 与进程内 Binder 通过对象引用共享同一份 SchedulerCache 内存实例，实现零拷贝、零同步延迟的状态复用。相比独立 Binder 部署形态，ENO 消除了跨进程 API 往返与相应的序列化开销。

创新点 2：基于 etcd 语义的分层绑定容错策略。针对分布式调度中最易被忽视的绑定阶段异常，构建四层结构化容错链路：节点分区验证（Layer 0，预防层）通过 Bind 前置校验拦截节点归属漂移；同步指数退避重试（Layer 1，即时恢复层）处理 apiserver 暂态错误；异步 Reconciler 队列（Layer 2，后台恢复层）清理孤儿 Assumed 状态；Dispatcher 跨 Scheduler 实例回退（Layer 3，全局恢复层）通过清理 `scheduler-name` 注解触发全局重分发。四层机制形成本文所见分布式 Kubernetes 调度系统中首个结构化的绑定容错模型，并给出了核心不变量"任一 Pod 至多绑定到一个节点"的完整证明要点，明确了每一层如何依赖 etcd 的原子性语义维护不变量。

## 1.3　论文组织结构

本文共分七章，结构如下：

第一章绪论，即本章，介绍研究背景与意义、研究目标与主要贡献，以及论文组织结构。

第二章国内外研究现状，沿架构演进、批处理与混部、大规模一致性三条主线，梳理 Kubernetes 原生调度器、Volcano、Koordinator、Gödel 四种代表性调度器的架构与特点，简要介绍 etcd 的一致性模型与本文关键依赖的原子性语义，并汇总典型集群调度系统横向对比、明确本文的定位与差异化空间。

第三章 ENO 分布式调度器系统架构，系统阐述本文提出的 Dispatcher/Scheduler/Binder 三层架构、节点分区机制、以及基于 etcd 的三步事务写入模型（dispatching → assuming → binding），并配合三张原创系统图分别展示总体架构、Dispatcher 内部流程、单个 Scheduler 内部流程。

第四章基于 etcd 语义的一致性容错机制，是本文的核心章节之一，详细展开四层容错机制的设计、实现与不变量证明。

第五章面向大规模场景的进程内 Binder 架构，阐述独立 Binder 到进程内 Binder 的架构改造思路（ENO）、Cache 零拷贝共享机制、部署形态变化，以及 CLI 开关的可切换性设计。

第六章实验设计与评估，介绍实验环境、工作负载与评估指标，随后分「实验验证」与「性能评估」两部分：前者回答"方案是否正确"，通过绑定成功率、不变量 I 断言与故障注入专项实验验证四层容错机制的正确性；后者回答"方案表现如何"，给出 ENO 与 Gödel、kube-scheduler、Volcano、Koordinator 四种基线调度器的对比结果分析。

第七章总结与展望，回顾主要贡献，诚实讨论工作的局限性，并展望后续研究方向。
