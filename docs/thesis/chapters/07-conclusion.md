# 第七章 总结与展望

## 7.1 工作总结

本文以"基于 etcd 的分布式 Kubernetes 调度器研究与实现"为题，围绕多实例并发调度场景下的**一致性保证**与**大规模性能优化**两个核心问题展开研究。以字节跳动开源的 Gödel Scheduler 为基础平台，完成了如下三项主要工作：

**（1）分布式调度器架构的系统性梳理。** 第 3 章明确了 Dispatcher / Scheduler / Binder 三层架构下 Pod 的完整流转过程，特别指出整个分布式调度器**不依赖任何自研的分布式协调机制**，而是完全基于 Kubernetes 底层 etcd 通过 kube-apiserver 暴露的三种原子性语义（Pod / Node 注解的 `resourceVersion` 乐观并发、Watch 一致性视图、Bind 子资源的原子写入）。这一分析统一了后续章节的论证起点。

**（2）基于 etcd 语义的多层一致性容错机制。** 第 4 章针对分区归属漂移、Bind API 暂态失败、进程内偶发错误、本地重试耗尽四类典型威胁，设计并实现了包含节点归属前置校验（Layer 0）、同步重试（Layer 1）、异步 Reconciler（Layer 2）、跨实例回退（Layer 3）的四层容错框架，并给出了核心不变量"任一 Pod 至多绑定到一个节点"的完整证明。

**（3）面向大规模场景的 ENO 架构优化。** 第 5 章提出将原独立部署的 Binder 合并进 Scheduler 进程的架构改造，通过 CacheAdapter 桥接层实现 SchedulerCache 零拷贝共享，消除了跨进程 API 调用与序列化开销。改造保持了第 4 章一致性容错机制的完整性，并通过 CLI 开关 `--enable-embedded-binder=true/false` 支持在两种部署形态之间无缝切换。

第 6 章通过 KWOK 仿真下的 60 次基准实验，对 ENO 与四种主流调度器（Gödel、kube-scheduler、Volcano、Koordinator）在稳态吞吐、调度延迟、绑定成功率、资源开销四个维度进行了系统性对比，验证了本文架构改造的性能优势与一致性保证的可靠性。

## 7.2 主要贡献

回顾本文的三项主要贡献：

- **贡献 1**：**基于 etcd 语义的四层一致性容错机制**（第 4 章）。填补了分区调度器场景下节点归属动态漂移的一致性论证空白，给出了严格的核心不变量证明；
- **贡献 2**：**进程内 Binder 的 ENO 架构**（第 5 章）。通过 CacheAdapter 零拷贝共享消除跨进程开销，同时保持向后兼容与一致性保证；
- **贡献 3**：**大规模多调度器对比评估**（第 6 章）。基于公开的 KWOK 仿真平台完成 60 次实验，公开完整的实验方法学与原始数据，为后续研究提供可复现的基线。

## 7.3 局限性

本文工作存在如下局限，坦诚列出：

**（1）实验规模止于 s3（5000 节点）**。受本文实验资源与时间约束，未能扩展到 s4（10K 节点）与 s5（30K 节点）场景。虽然 Gödel 官方报告在 30K 节点下稳定运行，但本文暂无独立数据支撑 ENO 在该规模下的表现。若能扩展到 s5 规模，本文的性能提升结论将更具说服力。

**（2）工作负载类型覆盖有限**。本文主用 w2/w3 稳态负载，未系统性评估突发洪峰（w5）、Gang 调度（w6）、异构资源（w7）等复杂场景。特别是 w5 突发洪峰场景可以充分展示 Dispatcher 与 Scheduler 双向协作的调度弹性，本文未能覆盖是一项遗憾。

**（3）生产环境未验证**。本文所有实验均在 KWOK 仿真环境下完成，未在真实生产集群中验证。真实节点上的 kubelet 排队、容器启动开销、网络与磁盘 IO 干扰可能对结论产生影响。

**（4）一致性论证的形式化程度有限**。本文的一致性证明采用严谨自然语言 + 代码引用 + 状态机图的组合方式，未使用 TLA+ 等形式化验证工具。虽然本文的四个证明要点已经覆盖了主要故障场景，但形式化验证可能揭示某些边界情况下的时序漏洞。

**（5）ENO 与 Gödel 资源公平性的一维近似**。本文的公平对比策略是每 Deployment 的资源规格相同（Scheduler Pod 与 Binder Pod 都是 2 CPU / 4 GB），这一策略在**单 Pod 层面**保证了公平，但没有系统性量化**集群总资源开销**层面 ENO 因移除 Binder Deployment 带来的进一步节省。

## 7.4 未来工作

针对上述局限，未来的工作方向包括：

**（1）扩展到超大规模场景**。将实验规模扩展至 s4 / s5（10K-30K 节点），验证 ENO 的水平扩展性上限。可考虑与拥有真实生产集群的机构合作，在生产环境中进行灰度部署验证。

**（2）复杂工作负载评估**。补充 w5（突发洪峰）、w6（Gang 调度）、w7（异构资源）场景的完整评估。特别是 w6 Gang 调度可以充分对比 ENO 与 Volcano 在批处理场景下的表现。

**（3）Binder 内存压力自适应**。当前 ENO 的 Binder 与 Scheduler 共享同一进程内存，若集群规模进一步扩大导致 SchedulerCache 显著增长，可能需要在 Scheduler 与 Binder 之间引入更细粒度的内存共享策略（例如按分区分片的 SchedulerCache）。

**（4）异地多活 Dispatcher**。当前 Dispatcher 采用单实例 Leader Election 模型，对跨地域场景不够友好。可探索多 Dispatcher 分区协同的架构，将节点分区表本身也做分区化管理。

**（5）形式化一致性验证**。将第 4 章的 Layer 0/3 时序性质用 TLA+ 显式建模并验证，进一步夯实一致性论证的严谨程度。

**（6）与调度策略研究结合**。本文侧重于调度器的架构与一致性，未涉及具体的调度策略（如资源感知、拓扑亲和、拥塞控制等）的创新。ENO 架构为后续在其上叠加具体调度策略研究提供了良好的基础平台。

## 7.5 结束语

大规模分布式 Kubernetes 调度器是一个既有工程价值又有学术意义的方向。本文通过对 Gödel Scheduler 的分析、扩展与优化，尝试在**一致性保证**与**大规模性能**这两个维度上给出严谨的答案。诚然，本文的工作只是这一广阔领域中的一小步，希望所公开的架构分析、容错机制与实验数据能够为后续研究者提供有意义的参考。
